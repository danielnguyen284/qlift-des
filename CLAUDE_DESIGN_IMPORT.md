## Controlling instruction

Create a reusable design system named `QLIFT Core Design System v0.1` from this repository. This is design-system setup and validation only; do not design the complete website or CRM.

Treat values marked `AUTHORITATIVE` as locked. Put every generated digital value - type sizes, spacing, breakpoints, radii, elevation, control sizes, density, and motion timing - into a clearly separate `PROPOSED` group until reviewed.

Build reusable component families for Shared, Public, and Admin/CRM surfaces. Public must support image-first homeowner storytelling and very low copy density. Admin/CRM must support compact operational scanning, status, owner, next action, dates, tables/list alternatives, detail records, activities, documents, approvals, and audit history without looking like a marketing page.

Validate the system with exactly two compact specimens:

1. Responsive Public header, full-bleed panoramic hero, and consultation-form fragment.
2. Admin shell, lead table/list, lead-detail header, activity segment, and loading/empty/error/permission/confirmation states.

Use honest placeholders. Never invent products, specifications, standards, certifications, projects, people, metrics, prices, contact details, warranty terms, SLAs, or service claims. Label concept imagery `Hình ảnh định hướng` wherever it could be mistaken for real work.

Return a token ledger, component inventory, states, responsive rules, accessibility notes, asset rules, source conflicts, and missing-production-input register. Do not publish automatically and do not proceed to full product-screen generation.
